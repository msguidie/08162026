# `splendor_ai`

Reinforcement-learning stack for the custom Splendor variant served by
`server/gameLogic.js`.  This directory currently contains the first
milestone — the **rules engine** and the **cross-language validation
harness** that gates everything else (see `docs/PLAN.md` §4).

```

               test_actions.py test_view.py test_replay.py test_perf.py
               oracle.py positions.py
```

Everything is importable from the repository root:

```python
from splendor_ai.rules import engine as E, view as V
state = E.new_game(4, "TEAM", "ADJACENT")
mask  = E.legal_mask(state)            # 65 bools
E.apply(state, E.legal_actions(state)[0])
obs   = V.public_view(state, player=0)
```

## Rules engine & validation

### What it is

`splendor_ai/rules/` is a bit-exact Python re-implementation of
`server/gameLogic.js` — the single source of truth for this variant.  It is
dependency-light on purpose: the hot path uses plain Python ints and lists,
numpy appears only in optional helpers (`legal_mask_np`) and later in batch
encoding.

| module | contents |
| --- | --- |
| `cards.py` | `CARDS` (ids 0–89) and `TILES` (ids 0–9) generated by the same `addCycle` recurrence as the server, plus a Node-diffing self test |
| `actions.py` | the 65-way discrete action space and the compact-replay bridge |
| `engine.py` | `GameState`, `new_game`, `legal_mask` / `legal_actions` / `is_stuck`, `apply`, `resign`, `timeout`, `to_protocol`, `from_replay_code`, `replay`, `rating_changes`, team scoring |
| `view.py` | `public_view(state, player)` — the per-seat information set |

### Action index table

65 discrete actions.  The numbering is fixed forever; do not renumber.

| index | action | encoding |
| --- | --- | --- |
| 0–9 | take 3 distinct colours | all `C(5,3)` triples, lexicographic: `012 013 014 023 024 034 123 124 134 234` |
| 10–19 | take 2 distinct colours | all `C(5,2)` pairs, lexicographic: `01 02 03 04 12 13 14 23 24 34` |
| 20–24 | take 1 gem (forced short take) | colour = `index - 20` |
| 25–29 | take 2 of the same colour | colour = `index - 25` |
| 30–41 | reserve a face-up board card | `30 + tier0*4 + slot` (tier-major; `slot` = position in the row, left→right) |
| 42–44 | reserve blind from a deck top | `tier0 = index - 42` |
| 45–56 | buy a face-up board card | `45 + tier0*4 + slot` |
| 57–59 | buy own reserved card | `slot = index - 57` |
| 60–64 | choose a noble tile | `state.tiles[index - 60]` — only while a multi-noble choice is pending |

Colours are `0=Indigo 1=Jade 2=Amber 3=Rose 4=Violet`, matching
`src/types.ts::GEM_NAMES`; index 5 of a gem array is gold/wild.
Resign and timeout are **not** policy actions (the server has no such game
action); `from_replay_code` maps the replay codes `X`/`T` to the sentinels
`ACTION_RESIGN = -1` / `ACTION_TIMEOUT = -2`, and `E.step()` dispatches them.

`legal_mask(state)` reproduces exactly the set of actions the Node server
would accept as a complete turn action — including the forced short takes at
8 and 9 tokens, the take-2-same stack minimum, and the fact that only tile
choices are accepted while a post-buy noble choice is pending.

### Rule subtleties this port reproduces

Things a naive port gets wrong — each is covered by a named test:

1. **`advanceTurn` runs after *every* action**, not only after a buy.  A noble
   left unclaimed by an earlier multi-noble choice is auto-claimed by the next
   gem take or reserve.
2. **`CHOOSE_TILE` requires `turnAction.type === 'BUY'`.**  A gem take or a
   reserve leaves `turnAction === null`, so if such an action qualifies *two or
   more* nobles the pending choice is **orphaned**: no tile choice is accepted,
   the ordinary actions stay legal and the turn does not advance.  Reachable
   only after a three-noble choice; hit 16 times in the validation run.
3. **`_pendingTileChoice` survives game over.**  `finishTurn`'s GAME_OVER
   branches `return` before the field is cleared, so the final client view
   still carries a stale pending choice.
4. **`payForCard` uses the discount from *before* the purchase**, and spends
   colour tokens before gold, colour by colour.
5. **`ENTER_RESERVE` gold rule**: gold is granted only when `gold > 0` **and**
   the player holds fewer than 10 tokens — and it is taken *before* the card is
   picked.  Reserving at exactly 10 tokens is still legal, it just pays nothing.
   There is no discarding in this variant.
6. **Board refills append to the end of the row**, so the remaining cards shift
   left and slot indices are not stable across a turn.
7. **Gem-take validation is sequential but order-independent.**  The server
   feeds the colour list through `canSelectGem` one at a time; the harness
   brute-forces every ordering of every multiset (~4.3 M orderings in the last
   run) to license the canonical sorted representative behind each take index.
8. **Forced short takes.**  At 8 tokens only 2-takes are legal, at 9 only
   1-takes, at 10 nothing.  A 2-different take is otherwise legal *only* when
   no third colour has supply; a single is legal only when the colour has ≤ 3
   left and no other colour has any.
9. **TEAM final rounds are revocable, ONE_V_TWO ones are not.**  If the 2v2
   condition (`total > 30 && secondScore >= theirs`) lapses while the rest of
   the round plays out, `finalRoundTriggeredBy` is cleared and play continues.
10. **INDIVIDUAL game over leaves `gameResult === null`** — winners come from
    the `calculateRatingChanges` ordering (score desc, then *fewer* cards).
11. **`getTeamStats` uses `-Infinity`** for a team without exactly two members
    (the 1v2 solo), and `-Infinity >= -Infinity` is true in JS.
12. **`calculateRatingChanges` treats an empty `winningTeamIds` as truthy**
    (JS array truthiness), so a team game that ends with no qualifying team
    pays 3 to everyone instead of falling through to the individual ladder.
13. **`processResign` in INDIVIDUAL** returns the tokens to the bank, discards
    cards/reserved/nobles, zeroes the score, shifts `roundStartPlayer` if the
    leader resigned, and ends the game below two active seats — it never
    triggers a final round and never bumps `turnNumber`.
14. **Team-mode resign is an instant forfeit** (`GAME_OVER` with a
    `gameResult`), regardless of whose turn it is.
15. **Stuck seats are real.**  10 tokens + 3 reserved + nothing affordable
    leaves the server with no accepted action and no PASS.  `is_stuck(state)`
    detects it; the validation run hit 4,051 such positions.
16. **`_tileClaimed` is consumed by the broadcast**, not by the engine — it is
    attached to the action result and deleted from the state.

### Hidden information (`view.py`)

`public_view(state, player)` gives one seat exactly what it may know: full
detail for its own reserved cards, board-reserved cards of other seats (public
— everyone watched the card leave the market, so the engine tracks a
`reserved_public` flag), and only the **tier** of a deck-reserved card
(`RESERVE_FROM_DECK` announces the tier).  Decks are never exposed beyond
`deckCounts`, and a pending noble choice is shown only to the acting seat.

### Reproducing a recorded game

`new_game(..., setup={'board':…, 'decks':…, 'tiles':…, 'first':…})` bypasses
the shuffle; `decks` are in **server order** (`pop()` takes the last element),
matching `docs/REPLAY_FORMAT.md` §1.  `E.replay(json)` takes a stored replay
file verbatim and returns the final `GameState`.

### Performance notes

* `legal_mask` allocates one 65-element list and nothing else; the 30 take
  patterns are precomputed and gem-take legality is closed-form.
* Per-player colour discounts are cached and updated incrementally.
* Card costs are precomputed as non-zero `(colour, amount)` pairs so
  `can_afford` iterates ~2.4 entries instead of 5 and bails out early.
* `GameState.clone()` is a shallow structural copy (card ids are ints);
  > 200 k clones/s.
